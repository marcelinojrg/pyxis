# Peta Dokumentasi Pyxis

Gunakan dokumen berikut sebagai sumber utama:

1. `PRD.md` — scope produk, user story, acceptance criteria, dan out-of-scope.
2. `ARCHITECTURE.md` — arsitektur aplikasi, data, auth, upload, dan deployment.
3. `DESIGN.md` — sistem visual, responsive, aksesibilitas, dan copywriting.
4. `ONLY_ME.md` — status implementasi, known issue, dan backlog lokal.

## Standar engineering

- `FOLDER_STRUCTURE.md` dan `COMPONENTS.md`
- `CODING_STANDARDS.md` dan `TYPESCRIPT.md`
- `DATABASE.md`, `SERVICES.md`, dan `AUTHORIZATION.md`
- `SECURITY.md`, `FILE_UPLOADS.md`, dan `PERFORMANCE.md`
- `TESTING.md`, `TEST-MATRIX.md`, dan `CONTRIBUTING.md`
- `DEPLOYMENT.md`
- `STACK.md` dan `VERSIONING.md`

## Aturan sinkronisasi

- Jangan menduplikasi status implementasi di banyak dokumen. Status operasional berada di `ONLY_ME.md`.
- Jangan mendokumentasikan fitur di luar `PRD.md` sebagai fitur aktif.
- Jika kode dan dokumen berbeda, verifikasi kode lalu perbarui dokumen sumber yang paling dekat.
- Dokumen lama sistem event tidak berlaku untuk Pyxis dan harus dihapus, bukan diganti nama.
- Pekerjaan email ditunda sampai ada instruksi terpisah.
